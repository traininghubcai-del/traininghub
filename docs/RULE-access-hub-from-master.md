# RULE — Access Hub roster comes from the MASTER

**Status:** Accepted · 2026-07-13
**Companion to:** `docs/ADR-master-workbook.md`, `docs/RULE-classes-and-registrations.md`

## The rule

The Access Hub billing panel (Territory Managers + Regional Managers in
`data/access_hub.json`) is **built from the real MASTER-derived files — never from
fabricated names.**

- **Territory Managers** ← `data/employees.xlsx`, rows where `Position == "Territory Manager"`.
  Region = their `Work_Location`. Account prefix `TM-40101+`.
- **Regional Managers** ← `data/employees.xlsx`, rows where `Position == "Regional Sales
  Manager"` (labeled "Regional Managers" in the UI). Region = their `Work_Location`.
  Account prefix `RM-50101+`. They are their own billable-seat category (`rms[]` in the JSON).

> **Dealers are NOT hub seats (2026-07-20).** Dealers never log into the hub — they are
> signed up by their Territory Manager and only *receive* their class info (email/materials).
> When a TM registers them, the dealer directory (`data/dealers.xlsx`, 224 rows) auto-fills
> their details. So no dealer access codes are minted and no `DLR-` seats exist. `dealers`
> stays in `access_hub.json` as an empty list; `dealers.xlsx` is directory data only.
> Billable seats = **TMs + RMs** (28), not 252.

Both source files are themselves generated by `tools/build_from_master.py` from
`_data_in/MASTER COPY  Training Hub Info Phase 1.xlsx`. So the chain is:

```
MASTER workbook
  └─ build_from_master.py ─► employees.xlsx + dealers.xlsx
        └─ reset_access_hub_from_master.py ─► access_hub.json
             (23 TMs + 5 Regional Managers = 28 billable seats; dealers are directory-only, not seats)
```

## Why

Everything in this product traces to one human-edited source (the MASTER). The Access
Hub used to seed 30 invented TMs + a dozen invented dealer companies into
`access_hub.json` on first load, which put fake people in the billing view. Removing
that keeps the "one source, zero drift" guarantee: no runtime file invents data.

## How to apply

- **`src/access.py` never fabricates.** `_seed()` reads `employees.xlsx` (via
  `_read_tms()` / `_read_rms()`) for the TM + RM roster. There are no hard-coded name
  lists, and dealers are no longer seeded as seats. On first load with no
  `access_hub.json`, it builds the real roster.
- **To rebuild the roster:** `./.venv/bin/python tools/reset_access_hub_from_master.py`
  (overwrites `access_hub.json`; backs the old one up to `_archive_data/reset_backups/`).
- **The full reset chains it:** `tools/reset_all.py` runs `build_from_master` →
  `make_codes` → **`reset_access_hub_from_master`** → wipe DB → regen mirrors → chat sync.
  Edit MASTER → `reset_all.py` → restart. That is the only supported way to change the roster.
- **`access_hub.json` is the live ledger after the build.** Adding/revoking seats in the
  `/manage` Access Hub UI writes there. Re-running the reset is a **reset, not a merge** —
  it replaces hand-added seats and re-mints access codes. Only run it after a MASTER change.
- **Seat count is real, not a sample.** All seats are created `active: True`, so the
  panel currently shows **28 billable seats** (23 TMs + 5 Regional Managers). Dealers are
  not seats — they don't log in. Revoke unwanted ones in the UI; do not trim the source
  lists to fake a smaller number.
