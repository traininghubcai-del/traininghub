Sharing & printing a classOne button next to “Register your team”

Share / Print class details opens a print-ready sheet for that class. If the class has vendor artwork uploaded, the sheet is two exact pages:

Page 1 — the flier

  • Vendor artwork, full page, nothing else on it
  • Sized so it can never spill onto a second sheet
  • Print page 1 only for a clean hand-out

Page 2 — QR + details

  • QR code straight to this class's registration page
  • Date, time with timezone, venue, instructor
  • “Free event · lunch included” block

No flier uploaded? The sheet is simply the QR page — nothing looks missing.

Editing a class

Open a class → Admin lens → change any field → Save changes. It shows you exactly what will change and asks for the code again before writing:

You're about to change 2 fields on this live class:

  CAPACITY        20 → 24
  CLASS ADDRESS   (empty) → 1200 S Caraway Rd, Jonesboro, AR

  Enter the Admin access code to apply these changes
  [ •••••• ]  Confirm & save   Cancel

Why it asks twice

  • An unlocked laptop can't silently rewrite a live class
  • You see the change before it happens, not after
  • Only changed fields are sent — no stale overwrite

Class address is special

  • Stored separately from the schedule table
  • Overrides the branch venue for that class only
  • Clear it and the class falls back automatically

The Admin lens also carries the full roster with contacts, custom flier upload, and remove-a-registration.

Adding a classThree answers, everything else inherited

With ADMIN-VIEW on, ADD A CLASS appears under the page title. You supply branch, class name and date. The rest is copied from the classes already running at that branch:

Branch:  Nashville, TN
Name:    HEAT PUMP DIAGNOSTICS
Date:    2026-12-08

Inherited automatically →
  region Nashville · state TN · timezone CST · weekday TUESDAY
  venue NASHVILLE BRANCH · host “Hosted by M&A Supply — Nashville, TN”
  level Level 1 · instructor Terry Jones

The class is live immediately — it appears on the public list, its page works, and it can be registered for.

Optional fields — capacity, start/end time, instructor, street address, notes — override the inherited values when you fill them in.
7

Reminder lettersPrintable, personalised, and counted

At the bottom of the Admin lens: ✉️ Send reminders (PDF). It confirms twice, then downloads one letter per student.

What's in each letter

  • “You are 42 days away from your class”
  • Student's name, company and role
  • Full class details incl. instructor
  • What's included · what to bring
  • Who to call, with the phone number

How it's counted

  • Generating is the send — there's no mail system yet
  • Logged to the same ledger the future email sender will use
  • One reminder = one day, however many times you click
  • Shows up as “Last reminder” + count on the master table
When email is switched on, it attaches to this same ledger — so the counts you're building now stay correct and nothing has to be reconciled.

Closing the class — two steps

1 · Submit class info

  • Saves attendance, pass/fail, score and notes
  • Locks the sheet
  • Edit any grade and it re-arms for re-submit

2 · Close class

  • Unlocks only once every student is graded
  • Marks attendance and grades final
  • Reopen to fix a grade if something was wrong
Rules the system enforces: grading opens only after the class date has passed · a student marked absent can never be marked passed · scores stay within 0–100 · close-out is blocked while anyone is ungraded.

Print roster produces a numbered sign-in sheet with a signature column and four blank rows for walk-ins.

Running & verifyingStart it, check it, trust it

cd "_MandA_AUG_3/app"
./.venv/bin/python server.py          # then open http://127.0.0.1:8000

./.venv/bin/python tools/data_audit.py --server   # 30+ checks, exit 0 = clean

Refreshing from John's workbook

Drop the new MASTER COPY … .xlsx into _data_in/ and run:

./.venv/bin/python tools/build_from_master.py
  → rebuilds the class schedule, dealer directory and personnel list
  → derives any missing timezone from the branch, and refuses to build
    if one can't be determined
Rebuilding replaces the class schedule. Registrations are untouched (they live in the database), but if a class's ID changes, its existing registrations become orphans — the audit flags that. Back up data/registrations.db before a rebuild.

The access codes

Admin is CORP7000; FSR is MAA. They are separate on purpose and do not cross — an FSR grades their branch, an admin rewrites the schedule, and one shared code made those the same privilege. Change them in data/hub_codes.json — takes effect on the next request, no redeploy.
